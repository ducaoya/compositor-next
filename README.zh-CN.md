# Compositor（跨平台）

[English](README.md) · **简体中文**

一个用于合成与修图的跨平台图像编辑器，以
[robbietilton/Compositor](https://github.com/robbietilton/Compositor) 的设计为基础 —— 那是原作者
用 Swift 写的、面向 macOS 的免费开源 Photoshop 替代品。

那个项目是这里一切设计的灵感来源与参照。本项目是它的从零重写，让同一个编辑器能跑在 Windows、
macOS 和 Linux 上：用 Tauri 2 + Vue 3 + WebGPU + Rust，而不是 AppKit + Core Image + Metal。

它读写原项目的 `.comp` 工程格式（版本 1–11），因此任一编辑器保存的工程都能在另一个里打开。

**协议：MIT。** 本项目是衍生作品，原项目的版权声明已完整保留在 [NOTICE](NOTICE)。详见
[署名与协议](#署名与协议)。

## 功能

- **`.comp` 工程读写** —— 图层组、图层蒙版、剪贴蒙版、参考线、逐图层不透明度与混合模式，兼容
  版本 1 到 11。
- **合成** —— 全部 24 种混合模式，按 Photoshop 的方式在 sRGB 空间合成；12 种调整图层（色相/饱和度、
  色阶、曲线、曝光度、渐变映射、颗粒、反相、黑白、色彩平衡、高斯模糊、动感模糊、添加杂色）；
  6 种图层效果；可绘制的图层蒙版；图层组。图层纹理与画帧都带完整 mip 链，因此缩小显示时
  不会出现摩尔纹。
- **绘制与选区** —— 画笔与橡皮擦（大小、硬度、不透明度、流量、笔迹平滑）；矩形、椭圆、套索选区
  以及魔棒，支持羽化、扩展、收缩；移动工具带吸附，以及缩放/旋转手柄；标尺、参考线、网格，
  以及放大到 800% 时出现的像素网格。
- **修图** —— 仿制图章（带对齐取样）、污点修复画笔（三种模式）、模糊、锐化、涂抹、减淡、加深、
  海绵，以及内容识别填充。修复、涂抹、模糊、填充的内核均移植自参考实现的 C 代码，并以纯函数
  形式在类型化数组上测试，无需 GPU。
- **滤镜** —— 高斯模糊、添加杂色、暗角、辉光、色调对比、镜头校正，每个都有自己的设置对话框。
- **导入** —— webview 能解码的格式，外加 SVG（按自身尺寸光栅化）与 TIFF（未压缩、PackBits、
  LZW、Deflate）；导出拼合 PNG 或 JPEG。
- **色相/饱和度的色彩范围分带** —— Photoshop 的六个范围，各有自己的色相、饱和度、明度与
  色带边界。
- **全程撤销**，一次手势一步。
- **崩溃也不会丢掉未保存的改动。** 只要文档有尚未落盘的改动，就会被快照到应用数据目录 —— 编辑
  停顿五秒后一次，且最多每三十秒一次 —— 下次启动时会把找到的快照列出来。恢复后的文档保存时写回
  它原本的工程，而绝不会写回恢复目录。
- **双击 `.comp` 即可打开**，并且是在已经运行的窗口里打开，而不是再起一个应用副本。
- **可以安装的更新**：从帮助菜单发起，先下载安装包，再用编译进应用的公钥校验签名，然后才替换。
  详见[更新](#更新)。
- **Photoshop 风格的界面**，内置英文与简体中文，可安装第三方语言包。
- **文件里有的内容都能完整往返**，即使当前版本还渲染不了。

### 明确不支持的格式，以及原因

按名称明确拒绝并给出原因，本身就是设计：打开后得到错误结果的截图，比直接说"打不开"更糟。

- **相机 RAW**（`.cr2`、`.nef`、`.dng` 等）—— 因许可而无法解码。最接近的纯 Rust 实现 `rawler`
  是 **LGPL-2.1**，静态链接进 MIT 二进制会让整个二进制变成 LGPL。本项目不链接它，导入路径会
  用文字说明原因。
- **HEIC** —— 解码器属于平台。Windows 的 WIC 有，参考实现也用了它；但从 Rust 侧接入尚未完成，
  因此 HEIC 文件会明确报错，而不是静默失败。
- **部分 TIFF** —— 分块、JPEG 与 CCITT 压缩、YCbCr、浮点采样、BigTIFF、多页文件，各自按原因拒绝。

### 尚未实现

- **PSD 与 PSB 导入**。格式有文档，参考实现也有读取器，本版本两者都没有。
- **选择主体**。需要在 webview 内跑 ONNX 模型，这是一项功能而不只是一处改动；若实现，将使用
  **U2Netp**（Apache-2.0），而绝不会用 RMBG-1.4 —— 后者许可禁止商用，与本项目协议不兼容。
- **文字工具**。文字图层可以完整往返，但还不能在画布内编辑。
- **图层复合、智能对象、视频、3D。**
- **文件管理器里的缩略图。** 资源管理器的缩略图提供程序必须是一个 COM DLL，而缩略图必须被*合成*
  出来 —— 24 种混合模式、12 种调整、蒙版、图层效果。要么把这些数学在 Rust 里写第三遍（现在已经有
  两份：TypeScript 与 WGSL，靠一个读取真实着色器的测试保持同步），要么让提供程序去调应用自己的
  渲染器，那意味着文件管理器每看一眼就要启动一个 webview。目前两种都不划算，所以 `.comp` 显示
  应用图标 —— 和以前一样。

| **三 —— 功能对等** | 部分完成：内容识别填充、仿制图章、污点修复、涂抹、暗角、辉光、色调对比、镜头校正、命令面板、色相/饱和度的色彩范围分带、标尺与像素网格。 |

**当前规模**：版本 0.1.0，274 个 TypeScript 单元测试、43 个 Rust 测试，以及 25 个在无头 Chrome 中

## 开始使用

环境要求：[Rust](https://rustup.rs)（Windows 上需 MSVC 工具链）、Node 22+、pnpm，以及 WebView2 运行时。

```sh
pnpm install
pnpm app          # 打开桌面窗口
```

也可以在浏览器里单独跑前端（会载入一个示例文档），无需桌面外壳即可调试画布、画笔和混合模式：

```sh
pnpm dev
```

其余脚本：

| 命令 | 作用 |
|---|---|
| `pnpm check` | 运行全部 Rust 与 TypeScript 测试 |
| `pnpm build` | 构建前端产物 |
| `pnpm tauri build` | 打包出可安装的桌面安装包。需要设置 `TAURI_SIGNING_PRIVATE_KEY`，因为安装包无论如何都要为更新器签名 —— 见[更新](#更新)。 |
| `node scripts/make-sample-comp.mjs` | 重新生成 `examples/sample.comp` |
| `node scripts/dev-browser.mjs` | 后台静默的 headless Chrome + WebGPU，用于脚本化界面验证 |

建议先打开 `examples/sample.comp` —— 它覆盖了混合模式、图层组、剪贴蒙版和图层蒙版。
`scripts/dev-browser.mjs` 启动的是**后台无窗口**的 Chrome（远程调试 + 软件 Vulkan 设备），
本项目的界面改动都是这样验证的，它不会抢占你的屏幕。

### 多语言

英文是默认语言，也是回退语言；简体中文随应用内置。其他语言就是一个 JSON 文件：**编辑 › 语言 ›
安装语言包…**，或把文件放进语言包目录后点击"重新载入语言包"。语言包可以只翻译一部分 —— 未翻译的
键会回退显示英文，而不是显示键名。详见 [docs/language-packs.md](docs/language-packs.md)。

## 二次开发

```
crates/core/     .comp 格式：manifest schema、校验、包 I/O
crates/shaders/  对 WGSL 做解析与校验，让着色器写错在测试阶段就失败
src-tauri/       桌面外壳，以及 webview 允许调用的命令
web/src/model/   文档、混合、调整、选区、工具 —— 纯逻辑，无需 GPU 即可测试
web/src/render/  WebGPU 合成器、WGSL、画笔、PNG 编码器
web/src/render/retouch/  修图内核：修复、内容填充、涂抹、色调、模糊 —— 纯函数
web/src/render/filters/  整层滤镜的内核 —— 同样以纯函数形式测试
web/src/io/     导入路径：SVG 光栅化与 TIFF 读取器
web/src/state/   session 状态中枢，以及前端与 Rust 的边界
web/src/i18n/    消息表与语言包机制
web/src/components/  Vue 界面
```

`web/src/model/` 里没有 canvas、没有 GPU、没有 DOM，所以大部分有意思的算法都能直接测试。
任何需要 GPU 的东西都在 `web/src/render/`；旁边的两个内核目录同样是类型化数组上的纯函数，
理由相同 —— 修复内核或镜头畸变都是算术，而算术不需要浏览器就能测。

**加一个工具**改三处：`web/src/model/tools.ts` 里加一条（标签键、快捷键、内联 SVG、
`implemented: true`），在 `web/src/components/CanvasStage.vue` 的指针状态机里加一个 `case`，
在 `web/src/components/OptionsBar.vue` 里加它自己的选项区。

**加一种混合模式**：`BLEND_MODES` 加一项、`web/src/model/blend.ts` 加一个分支、
`web/src/render/compositor.wgsl` 加一个 `case`。**加一种调整**结构相同：`ADJUSTMENT_KINDS`、
`buildLut` 或 `web/src/render/adjust.wgsl` 里的 `case`，以及 `AdjustmentPanel.vue` 里的一块控件。
两种情况都有一个 Rust 测试会去解析**真实的着色器文件**，一旦编号顺序错位就失败 —— 这是保证"在这个
编辑器里调好的工程，在另一个里打开仍然正确"的唯一办法。

**加一句文案**：在 `web/src/i18n/locales/en.json` 和 `zh-CN.json` 各加一个键。有测试强制两者键集合
完全一致、占位符完全一致。

**加一种导入格式**：在 `web/src/io/imports.ts` 里加一个分支 —— 要么是一个解码器（TIFF 与 SVG 各自
如此），要么是带原因的明确拒绝。`refusalFor` 就是"本版本不打开的格式"被点名的地方，原因与文案
都在语言包里。

**加一个像素用例**：在 `scripts/gpu-test.mjs` 里加一条，它通过 Chrome 调试协议驱动正在运行的构建。
它有两种读回方式，用哪一种本身就是断言的一部分：`renderAndRead` 读取文档分辨率的累积纹理，
`renderAndReadView` 截取屏幕上显示的画布 —— 缩放、平移、以及缩小画面采样了哪一级 mip，
只有后者能看到。

**改格式**：schema 在 `crates/core/src/manifest.rs`，规则在 `validate.rs`。任何"旧版本读不了"的改动
都要提升 `Manifest::CURRENT_VERSION`；任何旧版本必须容忍的字段都要可选。Rust 从不拼接面向用户的
英文句子 —— 它只返回翻译键和占位符取值，由语言包负责措辞。

各部分的衔接方式 —— 合成管线、CPU 绘制路径、存盘协议，以及三个只有在真实 GPU 上才会暴露的
bug —— 记录在 [docs/architecture.md](docs/architecture.md)。

**先跑测试。** `pnpm check` 会跑全部：Rust 测试覆盖格式与着色器，TypeScript 测试覆盖算法、图层树
和消息表。只有 GPU 才能体现的行为 —— 每种混合模式、每种调整、画笔、选区、变换手柄、蒙版绘制 ——
都是通过脚本驱动真实界面在 headless Chrome 里验证的，其中三个 bug 用其他办法根本发现不了。

## 更新

帮助菜单里的**检查更新**会拉取清单、比较版本并给出结果。版本比较遵循 semver，包括两个通常写错
的情形：`0.10.0` 比 `0.9.0` 新；正式版比自己的预发布版新 —— 因此 `1.2.0-rc.1` 会被提示升级到
`1.2.0`，而 `1.2.0` 不会被提示升级到 `1.2.0-rc.2`。这些逻辑在 `web/src/model/update.ts` 中并有
独立测试；拉取在 `web/src/state/session.ts` 的 `checkForUpdates`。

清单是"发布列表 + 每平台一个安装包"，也就是 Tauri 自带更新器使用的格式：

```json
{ "releases": [ { "version": "0.2.0", "notes": "…",
  "platforms": { "windows-x86_64": { "url": "https://…/Compositor_0.2.0_x64_en-US.msi",
  "signature": "…" } } } ] }
```

查找地址写在两处，必须保持一致：`src-tauri/tauri.conf.json` 里的 `plugins.updater.endpoints`
是*安装器*读取、并编译进二进制的清单地址；`web/src/state/session.ts` 里的 `updateEndpoint`
（默认同样是 `http://localhost:8787/latest.json`）是检查读取的地址，这样它的结果不靠外壳也能测试。
这个文件可以放在任何静态服务上 —— 开发时用本地服务，发布后放在下载页。

检查发现存在适用于当前平台的安装包后，帮助菜单里会出现第二项**安装更新…**。选择它会下载安装包、
在菜单栏里显示进度、校验签名并安装，然后重启进入新版本。没有人主动要求，就不会替换任何东西。

### 安装：发布时需要做什么

下载、签名校验与替换都已经接通。但签名需要密钥，而密钥是按项目生成的，所以发布时要做的就是：

1. 生成一次密钥对：`pnpm tauri signer generate -w ~/.tauri/compositor.key`。私钥保密 —— 它决定了
   更新能不能装 —— 把**公钥**填到 `src-tauri/tauri.conf.json` 的 `plugins.updater.pubkey`。
   仓库里已经有开发密钥：就是接通这一步时生成的那对，也是本地构建的包能覆盖本地构建的包的原因。
2. 把上面的清单发布到 `plugins.updater.endpoints` 指定的位置，每个平台一条，`url` 旁边写它的
   `signature`。
3. 构建时提供私钥：`TAURI_SIGNING_PRIVATE_KEY=… pnpm tauri build`。Tauri 会为每个安装包签名，
   并把签名写进 `bundle.createUpdaterArtifacts` —— 这一项是开着的，所以不提供密钥的
   `pnpm tauri build` 会直接失败，而不是产出永远装不上的安装包。

开发阶段采用自签名是刻意的：用自己的密钥签名的开发构建就是一条完整、可验证的路径，之后换成正式
证书只需用该机构生成密钥对并替换一个公钥。代码中没有任何地方假设这是开发密钥。

### 未保存的改动，与一次崩溃的代价

只要文档有尚未落盘的改动，就会被快照到应用数据目录的 `recovery/` 下，一个文档一个文件夹 ——
编辑停顿五秒后一次，且最多每三十秒一次。快照本身就是一个普通的 `.comp` 包，用与保存相同的暂存
与原子替换写入，外加一个记录它来自哪个工程的小侧车文件。

这让生命周期很短、恢复也很简单：改动写回自己的文件后快照就被丢弃；带着未保存改动关掉标签页时则
保留。因此启动时还留着的快照，必然属于丢失的工作，应用会就此询问：恢复，还是丢弃。恢复会把快照
当作一个记得自己来源的文档打开，保存时写回那个工程 —— 恢复过程自己绝不会覆盖任何工程，也不会在
恢复目录里留下工程的副本。理由见 [docs/architecture.md](docs/architecture.md)。

从资源管理器或文件管理器打开的 `.comp` 以命令行参数形式到达应用；第二次启动不会再起一个副本，
而是把路径交给已经运行的窗口，由它打开工程。两个进程同时写一个包，就是把包写坏的方式，所以这里
永远只有一个。

### 刻意不做依赖的两项

有两个本应用很想支持的解码器因为许可而放弃，而且都是**明确说明原因**地放弃 —— 导入路径会写出
理由，而不是泛泛地报错，因为许可问题不该由一个解码器替项目做决定。

- **`rawler`**（相机 RAW）是 **LGPL-2.1**。把 LGPL 库静态链接进 MIT 二进制会让整个二进制变成
  LGPL，因此本项目不链接任何 RAW 解码器，而是按名称拒绝 RAW 文件。
- **RMBG-1.4**（移除背景）的许可**仅限非商用**，无法与 MIT 发布共存。若将来实现选择主体，将使用
  许可宽松的模型（U2Netp 为 Apache-2.0）。

本项目其余所有涉及像素处理的代码，要么是自己的移植，要么是依据规范自行实现：修图内核移植自参考
实现的 C 代码（MIT），TIFF 读取器、SVG 光栅化、滤镜与版本比较均为本项目自行实现。Rust 侧没有
任何 C 依赖。
